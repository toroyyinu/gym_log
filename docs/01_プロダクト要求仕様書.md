## 1. 背景と目的

ジムで筋トレと有酸素運動を始めた。負荷（重量やマシンの設定）を少しずつ調整していくには、前回どの設定で何回・何分できたか、どれくらい辛かったかを覚えておく必要がある。しかし、記憶だけに頼ると曖昧になる。

そこで、iPhone の Safari で動き、ジムで片手でもすばやく記録できる自作の Web アプリを作る。

**目的**
1. 筋トレは「重量・回数・辛さ」を、有酸素は「時間・マシンの設定・辛さ」を、運動の合間の短い時間で記録できるようにする。
2. 次に同じ種目をやるときに前回の記録をすぐに確認でき、負荷を判断しやすくする。
3. 記録を蓄積し、重量や時間などの推移を振り返れるようにする。

**自作する理由（重視する価値）**
- 自分で作ってみたい（学習・ものづくり）
- プライバシー：記録を外部サーバーに送らない
- カスタマイズ性：必要な機能を自分で足し引きできる

## 2. 想定ユーザーと利用場面

- **ユーザー**：自分1人（筋トレ初心者、iPhone を使う）
- **主な利用場面**：ジムのトレーニング中。セット間の休憩の数十秒で、片手で入力する。電波が弱い場所でも使えることが望ましい。
- **副次的な利用場面**：自宅で履歴やグラフを見返す。必要に応じて PC でデータを分析する（CSV を利用）。

## 3. スコープ

### 3.1 含めるもの

| ID | 機能 | 概要 |
|---|---|---|
| F-1 | 記録 | 種目を選び、1セット（有酸素は1回）ずつ記録する。日時は自動で入る |
| F-2 | 前回記録の表示 | 種目を選ぶと、前回その種目をやった日の記録を表示する。入力欄の初期値にも使う |
| F-3 | 種目の登録 | 種目名、種類（筋トレ／トレッドミル型／バイク型）、鍛える筋肉、重量の刻み幅、固定メモを登録する |
| F-4 | 筋肉リスト | ジムでよく鍛える筋肉の一覧をあらかじめ用意する。筋トレの種目に複数紐づけられる。追加・削除・復元ができる |
| F-5 | 履歴の表示・修正・削除 | 日付ごと／種目ごとに記録を一覧し、部位・筋肉・有酸素で絞り込める。誤入力は修正・削除できる |
| F-6 | 推移グラフ | 種目ごとに、筋トレは最大重量、有酸素は選んだ項目の推移を折れ線グラフで表示する |
| F-7 | データの書き出し・読み込み | 分析用の CSV と復元用のバックアップ（JSON）を書き出し、バックアップから復元する |
| F-8 | ホーム画面への追加（PWA） | iPhone のホーム画面に追加して、アプリのように起動できる。オフラインでも動く |
| F-9 | 有酸素運動の記録 | トレッドミル型・バイク型のマシンで、時間・マシンの設定（速度・傾斜／レベル・回転数）・距離・カロリー・辛さ・備考を記録する |

### 3.2 含めないもの（将来の候補）

| 候補 | 優先度 | 備考 |
|---|---|---|
| バーベルなど、ダンベル以外のフリーウェイト | 低 | 今はやっていないが、将来やりたい。種目名で区別して「筋トレ」として登録すればそのまま使える |
| よくあるマシンの種目の候補（筋肉を設定済み） | 未定 | 外部レビューで提案あり（2026-10-13） |
| 筋トレのグラフで回数・総挙上量を見る | 未定 | 同上 |
| 履歴の期間での絞り込み | 未定 | 同上 |
| 時間だけを記録する種類（プランクなど）、クロストレーナー・ローイングマシン用の種類 | 未定 | 同上。クロストレーナーは当面「バイク型」で代用できる |
| インターバル（休憩）タイマー | 未定 | |
| 推定 1RM（1回だけ挙げられる最大重量の推定値）の表示 | 未定 | |
| 複数端末の同期・クラウド保存 | 未定 | プライバシー方針と両立する方法を別途検討する |

## 4. 機能要求

### F-1 記録
- 1件の記録 ＝ 筋トレは1セット、有酸素は1回（ひと続きの運動）とする。
- 共通の項目：**日時**（自動。後から修正可）、**種目**（登録済みの一覧から選ぶ）、**辛さ**（5段階）、**備考**（自由記述、任意）。
- 筋トレの項目：**重量**（kg）、**回数**（レップ数）。
  - 重量と回数は、＋／−ボタンで調整でき、数字の直接入力もできる。重量の＋／−の刻み幅は、種目ごとに設定した値を使う。
  - ダンベルの重量は **片手1本の重さ** を記録する（例：10kg を両手に持ったら「10kg」）。
- 有酸素の項目は F-9 を参照。
- 記録した直後は、短い時間だけ「取り消す」ことができる。

### F-2 前回記録の表示
- 種目を選ぶと、その種目を前回行った日の全記録を表示する。
- 入力欄の初期値は、前回の記録をもとに入れる（詳細は機能設計書を参照）。前回の記録を押すと、その値を入力欄に入れられる。
- 種目の固定メモ（シート位置など）もあわせて表示する。

### F-3 種目の登録
- 登録項目：種目名、種類（筋トレ／トレッドミル型／バイク型）、鍛える筋肉（筋トレのみ、複数選択）、重量の刻み幅（筋トレのみ、初期値 2.5kg）、固定メモ（任意）。
- マシンかダンベルかなどの区別は登録しない。種目名で見分ける。「種類」は、記録する項目を変えるためだけに使う。
- 種目一覧は **最近記録した種目を上** に並べる。まだ記録のない種目はその後ろに名前順。
- 有酸素のマシン（トレッドミル、エアロバイク、リカンベントバイク）は最初から登録しておく。
- 記録がある種目は削除できない。代わりに「非表示」にできる。

### F-4 筋肉リスト
- ジムでよく鍛える筋肉を、部位（胸・背中・肩・腕・体幹・脚・お尻）ごとにまとめた一覧をあらかじめ用意する（一覧は機能設計書を参照）。
- 1つの種目に複数の筋肉を紐づけられる（例：チェストプレス → 大胸筋・三角筋前部・上腕三頭筋）。
- 筋肉は、種目の登録画面で「その他の筋肉」として名前と部位を入れて追加する。追加した筋肉は、ほかの種目でも選べる。
- どの種目にも使っていない筋肉は、設定画面で削除できる。削除しても後から戻せる。

### F-5 履歴
- 日付ごと、種目ごとに記録を一覧できる。
- 部位・筋肉・有酸素で絞り込める。
- 記録を修正・削除できる。

### F-6 推移グラフ
- 種目を1つ選ぶと、横軸を日付とした折れ線グラフを表示する。
- 縦軸は、筋トレはその日の最大重量。有酸素は、時間・設定・距離・カロリーなどから選んで切り替える。

### F-7 データの書き出し・読み込み
- 記録を CSV で書き出せる（1行＝1件の記録。種目名・種類・筋肉も含め、Excel や R でそのまま分析できる形にする）。
- 復元用のバックアップを JSON（種目・筋肉・記録をすべて含む）で書き出し、そこから復元できる。復元すると現在のデータをすべて置き換える（実行前に確認する）。

### F-8 PWA
- Safari の「ホーム画面に追加」で、アプリのように起動できる。
- 一度読み込んだ後は、オフラインでも記録と閲覧ができる。

### F-9 有酸素運動の記録
- 種目の「種類」が有酸素（トレッドミル型／バイク型）のときは、重量・回数の代わりに次の項目を記録する。
  - トレッドミル型：時間・速度・傾斜・距離・カロリー
  - バイク型：時間・レベル・回転数・距離・カロリー
- 時間は分単位。必須は時間と辛さだけで、ほかはマシンによって表示されないことがあるので空欄でもよい。
- 前回の値を入力欄の初期値にする。グラフは項目を切り替えて推移を見る。
- 詳細は機能設計書「5.4 有酸素の記録項目」。

## 5. 非機能要求

| 分類 | 要求 |
|---|---|
| 操作性 | 1回の記録が、片手・数タップで終わること。ボタンは親指で押しやすい大きさにする。記録ボタンはスクロールしなくても押せる位置に置く |
| 視認性 | 辛さは **言葉と色の両方** で表す（色だけに頼らない）。選んだ段階の目安も文章で出す |
| プライバシー | 記録データは端末内にだけ保存し、外部に送信しない。アクセス解析などの外部スクリプトを読み込まない |
| オフライン | 電波がなくても、記録・閲覧・グラフ表示ができる |
| データ保全 | ブラウザの仕様でデータが消える可能性に備えて、ホーム画面への追加を前提とし、バックアップ（書き出し）を促す |
| 対応環境 | iPhone の Safari（ホーム画面から起動）を主対象にする。開発時の確認には Mac の Safari を使う |
| 費用 | 無料で運用できる |
| 保守性 | 自分で読んで改造できる、単純な構成にする（詳細はアーキテクチャ設計書を参照） |

## 6. 前提・制約

- 公開先は **GitHub Pages** とする。アプリのコードは公開されるが、記録データはコードに含まれず、各端末の中にだけ存在する。
- iOS の Safari は、ユーザーが一定期間操作しなかったサイトのデータを削除することがある。ただし、ホーム画面に追加した Web アプリは Safari とは別に利用日数を数えるため、使い続けていれば削除の対象にならない、と WebKit が説明している。
  - 出典：WebKit Blog「Full Third-Party Cookie Blocking and More」（2020-03-24） https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ （2026-10-12 参照）
- それでも、容量の上限を超えたときや端末の空き容量が少ないときなどには、データが自動で削除されることがある。
  - 出典：WebKit Blog「Updates to Storage Policy」（2023-08-10） https://webkit.org/blog/14403/updates-to-storage-policy/ （2026-10-13 参照）
  - このため、バックアップ機能を必須とする。
- 単位は kg・分・km・km/h のみとする。
- 日本（日本時間）で使うことを前提とする。旅行などで端末の時差が変わった場合の並び順は保証しない（アーキテクチャ設計書 5.1 を参照）。

## 8. 用語

| 用語 | 意味 |
|---|---|
| 種目 | 記録の対象となる運動。マシン1台、ダンベルを使った運動1つ、有酸素マシン1台など（例：ラットプルダウン、ダンベルカール、トレッドミル） |
| 種類 | 種目ごとに選ぶ記録の形。筋トレ／トレッドミル型／バイク型 |
| 記録 | 本アプリのデータの最小単位。筋トレは1セット、有酸素は1回 |
| セット | 筋トレで、1回続けて行った動作のまとまり |
| 回数（レップ数） | 1セットで動作を繰り返した回数 |
| 部位 | 筋肉をまとめる単位（胸・背中・肩・腕・体幹・脚・お尻）。絞り込みでは、有酸素の種目を「有酸素」として部位と並べて扱う |
| 辛さ | その記録の主観的なきつさ。5段階 |
| バックアップ | 復元用に書き出す JSON ファイル。分析用の CSV とは別 |
| PWA | Progressive Web App。ホーム画面に追加してアプリのように使える Web アプリ |
